# CineTube — Hermes Bootstrap

> Highest-priority Hermes project context. Keep this file short. Its job is to route Hermes into Project Atlas, not duplicate the project documentation.

## Mandatory bootstrap

Hermes MUST begin every new CineTube session in this order:

1. Read `ENTRYPOINT.md`.
2. Read `AGENTS.md`.
3. Read `atlas.json`.
4. Read `PROJECT_STATE.md`.
5. Read `docs/ATLAS.md`.
6. Resolve the active Goal from `atlas.json` and `.ai/goals/`.
7. Read `.ai/orchestration/hermes-policy.json` before any model selection, delegation, or LLM fallback.
8. Load only the minimum additional context required by the active Goal/Task.

Do NOT scan the whole repository or all documentation by default. Follow Lean Progressive Context and pointer-over-payload.

## Canonical authority

Hermes does not define CineTube model policy. The canonical sources are:

- `.ai/orchestration/model-policy.json`
- `.ai/orchestration/model-catalog.json`
- `.ai/orchestration/model-routing.json`
- `.ai/orchestration/fallbacks.json`
- `.ai/orchestration/hermes-policy.json`

`provider + model + effort` is an indivisible execution identity.

Never replace an approved provider/model pair with the same model through another provider.
Never use an unlisted model because it is newer, recommended, automatic, available, or cheaper.
Never invent a Hermes provider mapping that is not explicitly configured and verified.

If the exact approved provider/model pair cannot be executed by the current Hermes installation, STOP with:

`HERMES_NO_APPROVED_MODEL_PROVIDER_AVAILABLE`

Do not silently fall back to OpenRouter, Nous Portal, provider `auto`, or another aggregator/provider.

## Effort lock

- Command Code / GPT-5.6 Luna -> always `extra-high` according to the Atlas policy. If Hermes represents this level with a different supported runtime label, the mapping must be explicitly documented and must select the maximum intended project level; do not silently downgrade.
- All other paid approved models -> `high`.
- OpenCode free approved models -> maximum reasoning effort supported by the actual configured route.

Never reduce effort to save money. Save cost through T0, cheaper tiers, smaller context, cache/reuse, and stop-on-pass.

## Provider allowlist

Only the provider/model pairs present in `.ai/orchestration/model-catalog.json` are authorized. Current logical providers are:

- Google
- OpenCode
- Command Code

The logical Atlas provider name and the actual Hermes provider configuration must be explicitly mapped in `.ai/orchestration/hermes-policy.json` or the active Hermes profile. If no verified mapping exists, execution is blocked.

## T0 and escalation

Attempt deterministic evidence before LLM calls whenever applicable: compiler, tests, linters, schema validation, repository search, benchmarks, contract tests, SQL checks and `git diff`.

Escalate only because of objective failed evidence, an explicit risk gate, or a bounded failed attempt. Model self-reported uncertainty is not escalation evidence.

If acceptance evidence passes, STOP. Do not call a stronger model for reassurance unless the active Goal requires an independent review gate.

## Sensitive-context gate

Never send sensitive context to routes marked restricted in `model-policy.json` / `model-catalog.json`.

If sensitivity cannot be determined safely, classify the task as sensitive and use only an approved unrestricted route.

## Delegation

Before using Hermes delegation/subagents:

1. resolve the delegated Atlas Agent and Tier;
2. resolve the exact approved provider/model/effort;
3. verify that Hermes delegation is configured for that exact runtime identity;
4. verify the pair against `model-catalog.json` and the route against `model-routing.json`;
5. abort if Hermes would inherit or auto-select an unapproved model/provider.

A subagent using the wrong model/provider invalidates its output as Project Atlas evidence.

## Completion

Every model-backed result used as Goal evidence must record at minimum:

- Goal/Task ID
- Atlas Agent
- Tier
- actual provider
- actual model
- actual reasoning effort
- sensitivity class
- deterministic evidence before/after
- fallback reason, if any
- result: PASS | FAIL | PARTIAL | UNAVAILABLE | ABORTED

If the actual runtime identity cannot be proven, return:

`HERMES_MODEL_PROVIDER_POLICY_VIOLATION`

and do not count that execution as Goal evidence.
